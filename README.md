# 图表采集操作台（只读页面取数）

演示页是一张 Canvas 折线图（多系列、图例开关、拖拽缩放、悬浮提示）。
采集器**只用一个人能做的操作**取数：点击图例、拖拽框选、移动鼠标、读悬浮提示里的文字。
它不读图表内部变量、不读 React 状态、不读 data-* 属性，也不调用任何数据接口 ——
`collector/` 目录里没有任何 `import` 指向 `src/demo/data.js`（那个文件只给演示页和测试算标准答案）。

## 运行

```bash
npm install
npm run demo        # vite build && node server/index.mjs
# 操作台  http://127.0.0.1:4173/
# 演示图  http://127.0.0.1:4173/chart.html
```

其他脚本：

| 脚本 | 作用 |
| --- | --- |
| `npm run build` | 只构建前端到 `dist/` |
| `npm start` | 只启动已构建好的服务 |
| `npm test` | Playwright + ground truth 的端到端准确率测试 |

测试与采集可并行于服务，测试会自己在随机端口起一个静态服务。

### 容器内的额外环境变量

当前环境没有系统字体和 Chromium 依赖库，运行时需要：

```bash
export PLAYWRIGHT_BROWSERS_PATH=/workspace/.pw-browsers
export LD_LIBRARY_PATH=/workspace/.pw-browsers/libs/x86_64-linux-gnu
export FONTCONFIG_FILE=/workspace/.pw-browsers/fontconfig/fonts.conf
```

普通桌面环境不需要这些变量。

## 使用

1. 在操作台选系列、选时间范围（全部 / 最近 30 天 / 最近 60 天 / 自定义）。
2. 点「开始采集」。左侧实时显示当前目标、页面提示的原文与已确认计数；
   右侧表格按「已确认 / 缺失 / 无法确认」分类，读数与零值分开标记。
3. 每一行都有「在原图核对」：服务端另开一个浏览器，只显示该系列、缩放到该点附近、
   悬浮取提示，返回截图与提示文本，直接在弹窗里对照。
4. 「导出 CSV / JSON」包含 `series, exact_time_utc, ms, status, value, reason`。

演示图底部的开关可以用来加压，采集器不需要改任何坐标：

- **改变容器宽度**：画布宽度在「自适应 / 760 / 560 / 980」之间切换；
- **开启密集点**：2024-02-14 → 2024-02-17 期间每 2 小时一条额外采样（UTC 整点除外），
  页面用一行可见说明公布这段范围；
- **开启延迟提示**：提示先显示「正在读取提示…」，约 0.46s 后才给出内容；
- **卡住提示（故障演示）**：第一次出现提示后不再更新，用于验证「上一次的读数不得当成目标」。

## 取数规则

- **目标时刻来自页面可见文字**：图例里每个系列都带着节奏（`每日 00:00 UTC`、`每 2 天 12:00 UTC`），
  采样说明里带着密集段的起止时间和步长。采集器解析这些文字生成目标列表，节奏锚点用图表
  全量范围的起点，而不是用户选的窗口起点（否则两日节奏会整体漂移一天）。
- **一次只显示一个系列**：采集每个系列前用图例按钮把其它系列关掉，结束后恢复原状。
  这样提示里不会出现跨系列命中，重合点也不会互相干扰。
- **成功必须有提示时刻 = 目标时刻**：提示里自带 `YYYY-MM-DD HH:MM:SS UTC`，只有完全相等才记账。
  提示还停在上一个点、或者指在别的时间，一律不算成功，会先放大再问一次。
- **不能按坐标估值**：像素坐标只用来移动鼠标，值只从提示文字里读。
- **缺失与实际零值分开**：提示显示 `无记录` 记为缺失；显示 `0` 记为「零值」。两者都保留在导出里。
- **无法确认的点带原因**：例如「提示始终停在 …，指针移动和缩放后都不更新」、
  「邻近扫描：提示在 … 与 … 之间逐像素跟随指针，目标时刻没有出现读数（该处被跳过）」。

## 采集流程

1. 打开演示页，读图例（名称、节奏、开关状态）、可见范围文本、采样说明。
2. 逐个系列：只留该系列可见 → 双击回到全量 → 按目标时间分块，用拖拽把每块放大到相邻点不共像素。
3. 每个目标：把时间轴换算成像素位置去悬浮；等提示稳定后解析时间和各行读数。
   - 时刻对得上、有值 → 读数或零值；
   - 时刻对得上、`无记录` → 缺失；
   - 对不上 → 缩放到局部、再缩到极限各重试一次；
   - 仍对不上 → 在目标附近逐像素扫描：若提示会随时间移动但跳过了目标，判为真实缺口；
     若提示一动不动，判为「无法确认（提示卡住）」；若扫描中出现目标时刻的读数，则采纳。
4. 结束前恢复图例与缩放；有暂停/停止信号时在两目标之间响应。

绘图区像素边界不是写死的：`calibrate()` 用二分法探测“鼠标放在哪里会出现提示”，
得到左右边界，再配合可见范围文本换算时间。画布宽度、窄屏、2x DPR 都能用同一套逻辑。

## 目录

```
chart.html / index.html     两页入口
src/chart/                  演示图（Canvas 绘制、缩放、提示、演示开关）
src/console/                操作台（React）
src/demo/data.js            演示数据 + ground truth（只有演示页与测试使用）
src/shared/time.js          UTC 文本辅助
src/styles/                 设计变量与样式
collector/page.mjs          可见页面驱动：图例、缩放、悬浮、提示解析、像素校准
collector/plan.mjs          从可见文字解析节奏与密集采样说明
collector/index.mjs         采集作业：排程、分块、逐点确认、事件流
server/index.mjs            Express + SSE：任务、暂停/继续/停止、原图核对、静态资源
tests/collector.test.mjs    端到端准确率测试（含密集点、延迟提示、卡住提示、窄屏 2x）
```

## 已知边界

- 目标时刻只能来自页面公开的节奏文字与采样说明；页面没写的时刻不会被猜测。
- 提示卡死时无法区分“这一刻真的没点”和“提示不更新”，因此记为「无法确认」，不猜。
- 全量 4 系列（约 570 个读数）在容器里约 70 秒跑完。
